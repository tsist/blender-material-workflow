## 画笔提交的最小规格

1. 画笔写独立、可撤销的加图和减图；它们绑定材质 ID、图层 ID、目标 UV 身份、尺寸和 Non-Color。
2. 编辑数据和已提交数据分开放。提交时校验来源、旧版本和新像素摘要；保存快照。普通受管贴图和节点签名保持原核验。
3. 更新程序权重后，以两笔和一个未画区域做正例；错 UV、未提交、更改普通贴图、撤销及丢依赖做反例。冷开后复验 RGB 和贴图重建。
4. 初版验证单 UV 图。共享图集、UDIM、跨纹理集引用以及实时重算性能在独立实验后再定。

该阶段不继续堆重复链接。下次 Wiki 更新由新版本改变行为、可重复的原生正反例、或修复真实交接故障触发。未证实的预设、许可不明内容、以及外部引擎画质排名不入库。

### 画笔复制与复用的两道门

- **内容门：**保留既有像素、尺寸、色彩空间和受管结构检查；提交要核对新旧摘要，独立验证保存/打包及移位冷开。
- **写入范围门：**独立复制与显式共享分开。前者验证只改变副本；后者记录消费层并核对更新范围。给两份初始字节完全相同的遮罩各做一笔，再跑重算、保存、冷开和导出。[MW-002 探针和正反例](techniques/002-local-mask.md#复制后验收写入范围)。跨纹理集、图集与 UDIM 不扩大到首版验收。

## R30｜追加研究交接：开工前先读这四条

本轮通过已有实验、对照图和复跑命令的交接核验，不添加重复条目。Wiki 维持 15 张工艺卡、三个自动索引。首版的已验证交付仍是 Blender 工程和纯贴图重建；以下证据分开验收。

| 决策 | 现有证据 | 正式开发的判据 |
| --- | --- | --- |
| 程序和手工分开，通道显式列白名单 | [双箱原生](labs/toolbox-native.md)、[流痕通道对照](labs/weathering-native.md#r24单向沉积层必须显式限制写入通道)、[写入归属探针](techniques/002-local-mask.md#复制后验收写入范围) | 从一支画笔开始：加笔、减笔、留白；共享与独立各一组；验撤销、重算、冷开、再导出，非目标层/通道不变 |
| 按成片尺度判断辅助图和扩边，不能默认越高越好 | [同缝实烘](labs/uv-padding-native.md)、[掠射机位](labs/uv-padding-cycles-visual.md)、[切线基](labs/tangent-normal-uv-basis.md) | 定目标镜头，做一对同机位近景和整物距离，再核溢色和缝；实测切线法线，不将粗糙度结论通用于其他贴图 |
| AO 白色不代表射线命中，且遮挡物身份独立 | [投射合同](labs/texture-contract.md) | 同样件同时留局部命中图、接缝像素和几何分件对照；合并、拆件、移除分开验 |
| 流痕先在几何上走，再分别写 UV 岛；写入与缩图分验 | [世界方向、共边换岛、邻岛串色](labs/weathering-native.md) | 真工具箱至少一处可见跨缝试样，保留图集写入归属、邻岛、目标图峰值和宽度；离线试件不代替 Blender 或 GPU 的验收 |

**后续顺序：**先做可独立写入、撤销并能冷开的单 UV 画笔加减；再补上 Linux 正式 CLI 的隔离运行、并发和遮罩保护；然后定工具箱的画质标尺和入库证据。UDIM、跨纹理集、OpenPBR/Maya、目标 GPU 的 mip 和生产库放在各自有明确交付场景时处理，不算首版成果。生产代码和交付默认值在本阶段不改。
